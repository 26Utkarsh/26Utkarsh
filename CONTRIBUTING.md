# Contributing Guide

Thank you for your interest in contributing to my projects! I welcome collaborations, bug reports, feature requests, and improvements.

## 📋 How to Contribute

### 1. **Report Bugs**
- Check if the issue already exists
- Create a new issue with a clear title and description
- Include steps to reproduce, expected behavior, and actual behavior
- Add relevant screenshots or error messages

### 2. **Suggest Features**
- Use GitHub Issues with the `enhancement` label
- Describe the feature and why it would be useful
- Provide example use cases

### 3. **Submit Code Changes**
- Fork the repository
- Create a feature branch: `git checkout -b feature/your-feature-name`
- Make your changes following the code style guidelines
- Write clear, descriptive commit messages
- Push to your fork: `git push origin feature/your-feature-name`
- Open a Pull Request with a detailed description

## 🎯 Development Guidelines

### Code Style
- **JavaScript/TypeScript**: Use ESLint and Prettier configurations
- **React Components**: Use functional components with hooks
- **CSS**: Follow BEM naming convention or use Tailwind CSS
- **Comments**: Write meaningful comments for complex logic
- **Variable Names**: Use descriptive, self-explanatory names

### Commit Messages
- Use conventional commits: `type(scope): subject`
- Examples:
  - `feat(auth): add JWT verification`
  - `fix(dashboard): resolve chart rendering issue`
  - `docs(readme): update setup instructions`
  - `refactor(api): optimize database queries`

### Pull Request Process
1. Ensure your code follows project conventions
2. Add tests for new features (if applicable)
3. Update documentation if you've made changes
4. Link any related issues in the PR description
5. Wait for review and address feedback

## 🚀 Setup for Contributors

```bash
# Clone the repository
git clone https://github.com/26Utkarsh/[project-name].git
cd [project-name]

# Install dependencies
npm install

# Create your feature branch
git checkout -b feature/your-feature

# Start development server
npm run dev

# Run tests (if available)
npm test

# Build for production
npm run build
```

## ✅ Before You Submit

- [ ] Code follows project style guidelines
- [ ] Changes are tested locally
- [ ] Documentation has been updated
- [ ] No console errors or warnings
- [ ] Commit messages are clear and descriptive
- [ ] No sensitive information is committed
